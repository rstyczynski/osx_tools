= Changelog

== 1.6.0 — 2026-11-12

* Add an opt-in agent-review `AGENTS.md` with source-analysis, recovery-evidence, policy-proposal, verification, and authorized-application guidance, plus six portable example prompts. No AI runtime is added.

* Add central exclusions at `~/.config/tms/excludes` and nested project `.tmsignore` overrides, with last-match-wins include exceptions.
* Add `tms --explain PATH [--source ROOT]` showing the selected context, matching rule, and origin.
* Filter full backups and the newly cloned incremental tree; preserve source files and older snapshot entries.
* Count excluded files in per-source terminal and email reports; preserve compatibility with older six-column email reports.
* Save active policy text in `.rules.json` sidecars and carry policy metadata into restore output.
* Use NUL-delimited manifests and capture new included empty directories and unchanged files newly re-included by policy.
* Add temporary-fixture rule, incremental, restore, and email regression tests. The previously documented content quick-check and shared historical-metadata bugs remain.

== 1.5.1 — 2026-11-12

* Document the verified metadata/restore limitations and two outstanding incremental-backup correctness bugs: skipped same-size/same-mtime content changes and shared historical snapshot metadata. No backup behavior is changed by this documentation update.

* Send report emails in Courier with a bold heading so columns remain aligned.
* Put totals at the top and show common source-directory prefixes once, shortening table rows.
* Preserve full paths in the original plain-text logs and summary; retain the compact email body separately.

== 1.5 — 2026-11-12

* Add explicit `tms --scheduler on|off|status` controls with persistent launchd enable/disable state and actual schedule/next-run reporting.
* Add independent `tms --swiftbar on|off|status` controls; preserve unrelated plugins.
* Add `tms --access setup|status` for guided Full Disk Access setup and an automated check under the native background app identity.
* Include scheduler state, configured hours/timezone, next run, and wake behavior in email reports and the menu.
* Make setup reusable: preserve config, take destination from the current environment, and stop rewriting the login profile or embedding a personal recipient.
* Add lifecycle regression tests and document the manual macOS privacy grant step by step.

== 1.4 — 2026-11-12

* Add a native four-hour per-user launchd LaunchAgent with wake catch-up; remove the legacy TMS cron entry while preserving unrelated jobs.
* Add a noninteractive `--all` wrapper with kernel locking, private logs, persistent status, and final-summary emails through configured Apple Mail.
* Configure `TMS_REPORT_EMAIL` in the Bash login profile; keep the automation destination in a separate JSON config.
* Add SwiftBar status and backup-now actions for all sources or one source, plus summary/log shortcuts.
* Add a dedicated TMS Backup launcher app for scoped macOS privacy permission.
* Add setup email checks, temporary-fixture service tests, and installation/removal documentation.

== 1.3 — 2026-11-12

* Add read-only `tms --sources`: one row per known source with state, allocated size, regular-file count, and last successful backup.
* Add a final report with one row per source: status, changed files, backup type, elapsed seconds, and snapshot or failure/skip reason.
* Combine reports for `tms --all` and configuration-file `tms_batch` runs; standalone backups get a one-row report.
* Count transferred regular files using rsync statistics, and retain the statistics beside each snapshot.
* Preserve copy failure status through progress logging; unavailable file counts display as a dash.
* Preserve spaces and quotes in configuration-file source paths when trimming whitespace.

== 1.2 — 2026-11-12

* Separate each source's output with a visible divider and a source/destination header, including skipped entries.
* Add `tms --all` to run sequential backups of sources known at the destination.
* Bare `tms` now displays help without starting backups.
* Add `--help` (`-h`) and `--version`; reject unknown options and invalid backup arguments.
* Display the effective `backup_volume` when invoked.
* Record original source paths in `.source`; recover paths from legacy snapshots.
* Continue batch runs after missing or unrecognizable sources, with a summary and failure status.
* Preserve `latest` on copy failure, reject snapshot collisions, and retain hidden files when linking snapshots.
* Document setup, commands, destination layout, restore behavior, and file-based batch configuration.
* Add temporary-fixture regression tests for explicit and discovered sources and option handling.
